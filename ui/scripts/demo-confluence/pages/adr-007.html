Status: Accepted, November 3. Owner: Priya.

Context

Captures are recorded with their idempotency key after the processor answers. A retry that arrives in that window captures again (see Customers charged twice).

Decision

  • Reserve the key in a shared store before calling the processor; a second request with the same key waits for the first, then returns its result.
  • Keys live 24 hours. A key reused with a different amount is a client error (409), never a second capture.
  • The store is shared across instances (GitHub #12), so two pods can't both win.

Consequences

One more round trip per capture (about 3 ms). The shared store becomes something Checkout depends on, so it gets its own alert. Work: GitHub #11 (PR #37 in review), #12; Jira SCRUM-20 for the double click.
