Owner: Mei (Settlement). Tracked as: GitHub #22.

How you know

The 02:00 UTC reconciliation job ends failed in payments.job_runs with canceling statement due to lock timeout: waiting for AccessExclusiveLock on relation ledger_entries held by statement-export. It happens about once a week, always on a night the statement export runs long.

Why it happens

The merchant statement export starts at 01:55 UTC and holds ledger_entries until about 02:20. Reconciliation starts at 02:00 and waits for the same lock for 15 minutes before giving up. On a slow night the export is still holding it.

What to do

  1. Check the export finished: the statement-export row for tonight in payments.job_runs is succeeded.
  2. Re-run reconciliation by hand once it has. It takes about four minutes.
  3. If the re-run fails on anything other than the lock, page the Settlement on-call.
  4. Add a comment to GitHub #22 with the date, so we can see the frequency.

The real fix

Move the export to 01:30 UTC, or have reconciliation read from a snapshot. Neither has been scheduled; #22 has the discussion. Do not raise the lock timeout: it only moves the failure into the morning payout run.
