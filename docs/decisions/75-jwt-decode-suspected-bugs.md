# JWT decode suspected bugs (#75)

- **Items 1, 2 and 3 are fixed** as divergences under principle 4 (`docs/divergences/jwt.json`). A local run of `decodeJwt` on the issue's crafted tokens confirmed each one: JSON that was not an object was accepted, Node's base64 decoder skipped characters outside the alphabet, and invalid UTF-8 became U+FFFD. The header and payload now have to be base64url, UTF-8, and a JSON object.
- **The signature gets the same base64url check** (item 2: "The signature segment isn't decoded or checked at all"). Letters, digits, `-` and `_`, with `=` only as padding at the end, and a length that can be whole bytes. Anything else is `Invalid JWT: signature is not valid base64url`. The segment is still returned as the text it is. It is not decoded as UTF-8 and it is not verified. An empty signature passes that check, which is how `alg: none` is written (`signature: ""`). The header's `alg` is not read to allow the empty string: the empty string is valid base64url on its own, and this command still does not verify. A newline that sits inside the signature, not at either end of the whole token, fails here.
- **Trailing `=` padding is still accepted.** RFC 7515 appendix C allows it, and `util encode`'s base64url decoder already does. Whitespace is not skipped, unlike that decoder: a JWT segment has none (RFC 7519 §7.2), so the encode codec was not reused.
- **Item 4 is partly confirmed.** Accepting a `Bearer ` prefix, or trimming whitespace so the decode succeeds, stays refused. RFC 7519 §7.2 rejects extra characters, and `jwt decode -` already drops one trailing line ending. The issue's other fix is an error that names the prefix. A token that starts with `Bearer ` (any case, the space included) is `INVALID_INPUT`: `Invalid JWT: remove the 'Bearer ' prefix`. One with leading or trailing whitespace is `INVALID_INPUT`: `Invalid JWT: token has surrounding whitespace`. A trailing newline in the signature is that whitespace error, because the newline is at the end of the token. The prefix is named even when a newline also follows the token. A leading space is named even when `Bearer ` follows the space. Neither message includes the token. Recorded in `docs/divergences/jwt.json`.
