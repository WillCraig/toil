# Cut-off text keeps a way in on touch (#649)

- **The rule is three named ways in, and no fourth.** Every `data-truncate` element names, as the attribute's value, how its whole value is reached without hover: `expand` (a press on a toggle with `aria-expanded` in it opens the whole value wrapped inline), `detail` (it is, holds or sits inside a link that opens the view where the whole value shows), or `copy` (a Copy button beside it copies the whole value). A bare `data-truncate` or any other value is a title-only truncation and fails. This was chosen over unwrapping everything on coarse pointers alone because it keeps the compact rows on touch too, works with a mouse and a keyboard as well, and each way can be checked in the page rather than trusted from the stylesheet. Where none of the three fits, the text wraps and is not truncated. Written in `ui/README.md` (Cut-off text) and in the header of `ui/scripts/layout-check.mjs`; applies to every current and future `data-truncate` in Toil UI.
- **The layout check verifies the way, not just the word.** `inspect()` in `ui/scripts/layout-check.mjs` fails a `truncate-touch` finding when the named way is not in the page: no toggle for a cut `expand`, no link for a `detail`, no Copy button for a `copy`. An `expand` that cuts nothing in its box needs no toggle yet, since it hides nothing there; the check runs at 375, 768 and 1440px, so a chip is held at the width where it does cut. `inspect` is exported so `ui/test/truncate-touch.test.ts` can hold the check itself without a browser.
- **Each current use takes the lightest way that was already almost there.** Path and Url were already `copy` and only name it. A ticket chip with a link and a Classify sort-row head (whose item link it holds) are `detail`. The stand-up chips, the Toil project bar's description, a stand-up card's account name, an approval card's item titles and a ticket chip with no link are `expand`: the approval title especially stays in its card, because that card is where a person approves it, rather than sending them to the item and back. A stand-up chip grows its toggle only when a fact line is still hidden, or when the line is actually cut in its box, so chips that hide nothing stay uncluttered.
- **`font: inherit` comes before `font-size`.** The shorthand resets every font longhand, so an account size named above it computed at body size. `ui/src/components/summary.css`.
- **An opened stand-up chip does not repeat the row.** `linesBeyond` (`ui/src/components/truncate.tsx`) drops a fact line the folded row's text already contains, keeps a parenthetical time when the sentence is already shown, and drops a leading key the row shows. The row's text is read from the chip, with the toggle and the opened block removed, so there is no second string to keep in step with the markup. The title still unwraps in place.
- **Whether a line is cut is measured, the same way the layout check measures it.** `scrollWidth > clientWidth + 1` (or the height), on the truncation and on any `[data-truncate-text]` inside it. The old length check (`> 40`) and the hand-built `visible` string are gone: a long line that already fits grows no toggle, and a line that ellipsizes inside a box that fits still does.
- **The title, the description and the account stay text.** The way in is a More control with the same treatment as the stand-up's More (link colour, underline on hover, the app's focus ring), in the tab order only when the line is cut or open. Making the whole line the button gave every row a tab stop and no affordance. A permanent underline would draw an in-app action as a link, which principle 11 doesn't. `ui/src/components/truncate.tsx`.
- **The ticket chip's unlinked More, and the chip that is itself the link, have tests.** Callers pass `detail`, so those branches were unreached. `ui/test/ticket-chip.test.tsx`.
