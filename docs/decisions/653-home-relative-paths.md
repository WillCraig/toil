# Paths shown from the home folder (#653)

- **The server names the home folders once, in `api/info` (`homes`), and the page shortens.** `ui/src/home-path.ts` writes any path under one as `~/…`, in forward slashes. The alternative, a short form beside every path in every response, would add a field to each endpoint that returns a path (the worklog, exports, diagrams, assignments, agent install, npmrc) and to toil's own envelopes, which the page reads directly. The page already holds full paths for the Copy button, so `homes` tells it nothing new; the point is what is drawn, not what is held.
- **Two homes: HOME's and the account's own.** `homeFolders()` in `ui/server/server.ts` takes `os.homedir()` (HOME, or USERPROFILE on Windows) and `os.userInfo().homedir` (the account's, which HOME doesn't move). The demo runs Toil UI with HOME at `~/toil-demo-home`, and a repository clone or an assignment's folder under the real home would otherwise still show the account name. The longest match wins, so the demo's cache shows as `~/.toil-ui/…`. Both forms read `~`: which home a path is under isn't something a reader acts on, and Copy gives the exact path.
- **`~/` on every OS**, Windows included, rather than `%USERPROFILE%\`: toil's JSON paths use forward slashes, and PowerShell reads `~` too. On Windows (a home with a drive letter or a share prefix) the match ignores letter case, as the file system does; elsewhere it is exact. A path outside every home, including another account's `/home/someone`, is shown whole.
- **The tooltip shows the short form too; Copy copies the full path.** A hover tooltip appears while a mouse crosses the screen in a recording, so it is not "one press away". Copy is the press.
- **Where it applies:** every `<Path>` (What happened's page path, the worklog and stand-up export paths, a diagram's file, an assignment's clone folder), the folders a person typed, echoed back on New Toil project and Setup, the briefing's "Briefing settings from …" line, the repository paths in Assign, the agent install folder and program path, and the npmrc path after saving a registry.
- **Paths inside sentences, too.** `homeText()` writes a home folder from `~` wherever a path starts in a sentence (after a space, a quote, a bracket or `=`), in either slash. The page's `httpExecute` applies it to every envelope's error, fix and warnings, and the server-error reader (`failure()`) to the server's own messages, so every error any screen draws is covered in one place; `data` is left as toil sent it. The agent setup texts, from their own endpoints, get it where they are drawn. The layout check found these: toil's "No toil project applies to …", an adapter's "isn't installed beside Toil UI" and the Install dialog's command.
- **The Install dialog's command shows `~` and says so.** It is labelled the exact command run without a shell, and no shell expands `~`, so when the command was shortened the label adds that `~` stands for the home folder and Copy command copies it written out. An approval card must be honest about what runs (principle 2); this keeps it honest without putting the account name on screen.
- **Not shortened:** agent answers, and the Analyze prompt preview in Settings, which shows the exact prompt the agent receives. The sample sets no home, so its fixture paths, already written from `~`, show as they are. A data folder outside every home (`--data-dir`) shows whole. Matching is by text, so a path reported in its realpath form under a symlinked home would show whole too; toil's file service reports resolved paths, not realpaths, so none is known to.
- **The guard is the layout check.** So the next screen can't bring a full path back, `ui/scripts/layout-check.mjs` fails any view or state whose text, `title` or `aria-label` contains the home folders of the account running the check (in either slash), or the account name as a home folder in a path (`/Users/<name>`, `/home/<name>`). It runs in `npm run smoke -w ui` and `npm run verify:ui`; on real data in `verify:ui` that covers the clones and cache under the checkout. The account name elsewhere is not looked for: it may also be a person's name, a login in a URL or a branch prefix that the data rightly shows.
- **No principle or ship-skill rule for this:** the review asked whether CLAUDE.md should say a screen never shows the OS account name. No rule, the maintainer's call (2026-11-17); the layout check above is the guard.
