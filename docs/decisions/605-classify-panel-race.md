# How it's doing waits for its loaded panel in tests (#605)

- **The How it's doing tests wait for the panel that has loaded, not the first one.** The view shows a "not read yet" panel until the record loads, then a new one in its place. On a slow runner (the release PR's Windows Node 24 job, 2026-11-16) a test caught the first panel and read "not read yet" where it expected the figures; others held the first panel and waited on a button that only the second has. `doingWith` in `ui/test/classify-views.test.tsx` waits for the panel whose summary, or whole text, says what the test expects. With the sample's delay raised from 12 ms to 120 and 400 ms, all five of the describe's tests now pass, where three failed before.
- **The other tests in the file were left as they are.** With every sample call slowed tenfold, six tests elsewhere in the file (the agent's answers and the apply flow) run past Testing Library's one-second wait. None has failed on CI, and they wait on many calls in a row rather than on a stale element, so lengthening their waits was out of proportion to what it would fix.
