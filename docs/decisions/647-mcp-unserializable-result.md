# An MCP result that can't be serialized is a tool error, not a protocol error (#647)

- **The stand-in failure lives in core, `src/core/unprintable.ts`**, not in the MCP server, so the CLI's fix (#642) can call the same function and the two front doors can't drift. #642 was still open when this was written, so it keeps its own copy in `src/program.ts`; folding it onto this module is a small follow-up once both land. The wording is #642's, word for word, "couldn't be printed as JSON" included, so an agent sees the same error on either door.
- **It is a tool result with `isError: true`, carrying a small `INTERNAL` envelope**, never a JSON-RPC error. `data` is dropped. A failure that couldn't be serialized keeps its code, message and fix and drops its details. A write says the change may already have been applied and to check before retrying, as `TIMEOUT` and `CANCELLED` do for writes. If meta itself refuses, the last resort names only the command, as on the CLI. The stand-in also drops `meta.page` and `meta.summary` (the review's suggestion), since a cursor or summary attached to an error describes data it no longer carries; #642's copy keeps them, and the follow-up that folds it onto this module brings the CLI in line.
- **Whether the call wrote is read from the arguments as the client sent them**, with `writesForInput` in `src/core/run.ts`, the same function that words `--summary-file`'s result for a write. It was exported rather than copied, so the two can't disagree about one call. Where a `writesWhen` throws on the raw arguments it falls back to `def.writes`, as it already did.
- **The server checks with its own `JSON.stringify` of the envelope**, the one the text content already used, and sends the checked envelope as `structuredContent`. The stdio transport then serializes the JSON-RPC message, which nests the envelope two levels deeper. A result within those two levels of the stack limit could still pass the check and fail in the transport. That edge was left: probing for headroom would be a guess at the stack, and every result the issue's repro and the tests build fails the check by thousands of levels.
- **The test uses `connectMcp()`'s in-memory transport.** It doesn't serialize messages, but the handler's own `JSON.stringify` is what threw before, so the test fails without the fix (checked by reverting it: all three cases came back as `-32603`). A real stdio client was run by hand against the built bin, before and after.
