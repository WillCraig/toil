# Fewer Dependabot pull requests (#586)

- **Dependabot's updates are regrouped so a week brings at most a handful of pull requests** (the maintainer's ask, 15 November 2026: "consolidate more"). The first run of the file #591 added opened twelve, and each entry's `open-pull-requests-limit` hid more: about thirty pull requests were due, for some forty updates. `.github/dependabot.yml` is again the one file under `.github/` this PR touches, at the maintainer's request.
- **One npm entry for the root, the site and the feedback function** (`directories`), where there were three. A group then spans all three folders, so a package bumped in two of them (a font the site and Toil UI both use, `@types/node`) is one pull request, not two. The root entry already covered the `ui` workspace through the root lockfile: the first run's grouped PR bumped packages only `ui/package.json` names.
- **What ships is one group, `shipped`, not one pull request per package.** This reverses the default #591 made in the file's own header comment, where every bundled package and every Toil UI front-end library kept its own PR. They still arrive apart from dev tooling, so the review of what reaches a user stays separate; they no longer arrive one at a time. The feedback function's `@azure/*` runtime joins the group, since it is deployed. A package missing from the list arrives with `tooling`, so a forgotten entry costs a label, not an update.
- **Majors are one group, `majors`, for everything, shipped packages included.** They were never grouped before. A grouped PR passes or fails as one, so a major that needs work holds the others in that PR until it is fixed or dropped with `@dependabot ignore <package> major version`. That is the cost of one PR where there were a dozen, and it matches how #591 took its batch: everything at once, fixed forward.
- **GitHub Actions is one group with no `update-types`**, so majors arrive with the rest. Most pending action updates were majors (seven of nine), each its own PR.
- **Security updates are grouped too** (`applies-to: security-updates`), one PR per ecosystem. The first four security updates, on 13 November, arrived as four pull requests.
- **Not changed:** the weekly schedule, the 14-day cooldown on npm version updates, the `@types/node` major ignore, the label and the commit prefix. The npm entry keeps its limit of 5 and Actions its 3 (the site's and the function's limits went with their entries); neither is lowered, since that would hide pull requests, not consolidate them, and the groups can't reach either.
- **Group order is load-bearing.** Dependabot gives a dependency to the first group that takes it, and a group with `update-types` takes only those: `shipped` and `tooling` take minor and patch, and a major falls through to `majors`. GitHub's reference states the first-match rule; the fall-through by update type is not in the reference and was confirmed from public repositories that define a minor-and-patch group before a major one and get PRs for both. If it did not hold, majors would arrive singly, as they do today. Likewise a group spanning `directories` was seen on other ecosystems' pull requests, not npm's; if it did not hold here, a group would be up to three pull requests, one per folder.
- **Multi-ecosystem groups (npm and Actions in one PR) were left out.** The reference page for them could not be read, and a mistake in this file shows only after it merges.
