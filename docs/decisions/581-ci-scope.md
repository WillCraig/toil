# Docs-and-config PRs skip CI's long jobs (#581)

- **A PR that changes only docs and config skips Toil UI's gate and the database job** (the maintainer's call, 16 November 2026, after #608, a one-line change to `.github/dependabot.yml`, waited about an hour, most of it Toil UI's layout check). toil's own gate still runs on every PR, so the suites that hold docs to code (bounds, the command contract, hygiene, the skill) keep checking a docs change.
- **The list is `scripts/ci-scope.mjs`, and CI runs `main`'s copy of it**, read with `git show "$BASE_SHA:…"`, so a PR can't widen the list for itself. A PR that adds or changes the script runs everything, as this one does. A PR can still change `ci.yml` itself, as it always could; the review covers that.
- **Fail-closed at every step.** A push to `main`, a missing script on `main`, a diff that can't be listed, an empty list or an unreadable file all answer `full=true`. If the scope check fails, the long jobs skip and `CI ok` fails on the scope check, so a failure never becomes a pass. `CI ok` accepts a skipped long job only when the scope check succeeded and said `full=false`.
- **The list is narrow, and each entry says why it is safe**: `docs/decisions/` and `docs/briefs/`, `.claude/`, `CLAUDE.md`, `AGENT_DECISIONS.md`, `.github/dependabot.yml`, `functions/`, `infra/`, and `site/` except `site/src/lib/`. It was checked against what the two jobs read: Toil UI imports `docs/owi/schema.json`, `site/src/lib/skill-pages.mjs`, the root `CHANGELOG.md`, `skills/` and `src/`, and its chart test reads `docs/work-insights-proposal.md`, so none of those match; the root `README.md` ships in the tarball Toil UI's smoke installs, so it runs everything too. Other Markdown under `docs/` runs everything, since tests read some of it and new files appear. `test/ci-scope.test.ts` pins each of those as "runs everything".
- **Only a PR against `main` may skip**, and the diff lists both sides of a rename (`--no-renames`). A PR stacked on another branch could be pointed at `main` later without CI running again, and a file moved out of a path the jobs read would otherwise show only its new, skippable name.
- **The scope job uses the runner's own Node**, not `setup-node`: the script imports only `node:fs` and `node:url`, and skipping the install keeps the check to seconds.
- **The rule for other PRs is unchanged**: anything touching code, tests, the skill, package files or workflows runs both gates and the database job, and Windows, macOS and Node 26 still run daily and on the release PR.
