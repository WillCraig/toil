# One flag per file idea (#622)

- **Four file flags, one idea each** (the maintainer's call, 2026-11-16: "a global input file parameter that works the same way everywhere"). `--input-file <path>` (field `inputFile`, `-` for stdin on the CLI) is the local file a command reads; `--<flag>-file` is one field read from a file; `--path` is a path inside a remote repository; `--out <path>` is a file a command writes itself. `--dir` stays for downloads and the global `--output-file` stays the envelope. The integrations skill's Command Shape says so, so a new command starts there.
- **`--input-file` keeps the meaning eleven commands already gave it, widened, rather than a new `--input-json`.** The proposal the maintainer approved moved the JSON-document `--input-file` (Jira and Azure DevOps Server work-item create and update, Alation documents, Split flags, feedback) to a global `--input-json`, and gave `--input-file` to content. Both are "the local file this command reads", whatever it holds, so one flag serves both and those eleven commands don't break. A core-generated global flag was not built: each command still declares the field, because what it does with the file (read it as text, stream it, parse an inventory, upload its bytes) is the command's. `util`'s kit exports `inputFileOption` beside `inputFields` so a reading command can't spell it another way.
- **What moved to `--input-file`:** `util`'s `[file]` positional and `file` field (14 commands), `--file` on `classify run`, `prompt`, `stats`, `mix` and `projects brief`, `pivot`, `people suggest` (and `file` on `projects diagram check` and `save`), `--from <file>` on the inventory readers (`osv vulns`, `ossindex vulns`, `sonatypeiq evaluate`, `artifactory package outdated` and `license-check`), the three `categorize` commands and `classify scheme set`, and `--file` on the three `attach` commands. The MCP `classify` prompt's `file` argument is `inputFile` too.
- **`--<flag>-file`:** `util time business-days --holidays` (beside the repeatable `--holiday <date>`, which made the pair easy to misread), `classify run --verdicts`, `classify stats --backtest` and `--revised` became `--holidays-file`, `--verdicts-file`, `--backtest-file` and `--revised-file`. `--body-file`, `--jql-file`, `--fields-file` and `--allow-file` already fit. Core does not generate a `-file` twin for every text field: no command needed one, and it would double every tool's surface.
- **`--path` is a path inside the thing being read, never a file toil opens or writes** (the maintainer's call, 2026-11-16), so `git diff --path` (a pathspec), `util openapi --path` (an API path) and `artifactory --path` (an artifact pattern) fit it beside the repository paths, and nothing else was renamed. **`--path`** replaces `--file` on `pr comment-inline` (Azure DevOps, Bitbucket, GitHub), `bitbucket pr diff` and `git diff`, as Azure DevOps Server's `pr diff --path` already was. Toil UI's agent never offered `file` on a live tool; it now sees `path` on `bitbucket pr diff`, a path inside the remote repository and read-only, which it may narrow a diff by.
- **`--output-file` and `--summary-file` are the named exception to the `-file` suffix** (the maintainer's call, 2026-11-16): global flags that write a file (the envelope; the whole of `data`) rather than read one. Renaming them would break every script and agent config that uses them, for a naming tidy-up. The integrations skill says so beside the rule. They also overlap each other, which principle 3, sharpened in this PR, says not to have: folding `--summary-file` into `--output-file` is #638, deferred until the maintainer takes that break.
- **`--out`** replaces `--file` on `classify scheme export` and `projects export`, as `util encode`, `util c4 render` and the CSV reports already spell it.
- **Old spellings keep working on the CLI for at least one beta** (principle 7), through one mechanism instead of `--dossier`'s one-off: a `CliOption` lists its old spellings in `deprecated`, and a `CliArgument` names the flag that replaced it. The CLI registers them hidden, reads them into the field, lets the current flag win when both are given, and adds a `DEPRECATED_FLAG` warning naming the replacement. The routed alias `deps frisk` reads its routes' old spellings too. `argvFor` never writes a retired positional. The contract test still finds the old flags, so no divergence was needed; the contract's rows now record the new spellings.
- **MCP and the API take only the new field names**, as with dossiers (contract version 3): strict input refuses an old one as unknown, and the contract version goes to 4 with a migration row in `docs/command-contract.md`. Keeping old MCP field names would mean two fields for one idea in every tool's schema, which is the thing this change removes. The refusal's fix names the new field, as it does for `dossier`: `execute()` derives each command's renamed fields from its own retired spellings (`--holidays <file>` was `holidays`, now `holidaysFile`), so no second list can drift from them.
- **A group flag may not list retired spellings yet**: nothing registers them on the group, so the CLI refuses such a definition when it builds rather than let the old spelling be an unknown option. No group flag was renamed.
- **Not moved, and why:** `connections import <file>`, `classify scheme import <file>` and `projects import <file...>` keep a positional file. They are CLI-only commands a person runs, `connections import` reads a file outside the workspace by design (`docs/bounds.md`), and the file is the thing each imports. Moving them is a follow-up if the maintainer wants the rule with no exception. `classify scheme init --from <scheme>` keeps `--from`, since it names a scheme to copy (a name more often than a file), and `--from` stays the flag for a time, a ref or a branch (`dynatrace`, `saucelabs`, `util deps diff`, `util time cron`, `bitbucket pr create-many`, `classify mix`, `projects pivot`) and `connections import --from <tool>`.
- **`docs/work-classification-proposal.md` is unchanged:** it records the proposal as it was made. So is the README's "At a glance" run, which is a captured run of `0.1.0-alpha.2` and stays as it printed.
- **`ado commit create --file` (#618) becomes `--input-file` here with no old spelling kept**, since it hadn't been released.
